# Beotigi (버티기)

3인 하늘섬 생존 콘텐츠용 Paper 26.2 플러그인.

**접속하면 바로 플레이할 수 있다.** 서버를 처음 켜면 스카이블럭 월드와 시작 섬 3개(숲/바위/초원)를
플러그인이 알아서 미리 지어놓고, 플레이어가 처음 접속하는 순간 자동으로 그 중 하나에 배정되어
떨어진다. `/island` 명령어를 몰라도, 아무것도 몰라도 그냥 접속만 하면 게임이 시작된다.

핵심 원칙: **HUD 없음.** 퀘스트 창, 섬 안정도 게이지, 재해 카운트다운 바 같은 건 없다.
대신 "짧은 채팅 한 줄" 정도의 분위기 있는 안내는 있다 — 정확한 초 단위 숫자가 아니라
"바람이 심상치 않다..." 같은 대사에 가깝게. 자세한 설계 방향은 아래 "설계 철학" 참고.

## 요구 사항

- Paper **26.2** (build 121 이상 권장)
- **Java 25 이상** (Paper 26.x부터 Java 25 미만에서는 서버 자체가 뜨지 않음)
- Java/Maven 빌드: JDK 21 이상 (컴파일 타깃은 21 release)

## 빌드

```bash
mvn package
# target/Beotigi-1.0.0.jar 를 서버 plugins/ 폴더에 넣는다.
```

## 설치 가이드

1. **서버 준비** — [PaperMC 공식 사이트](https://papermc.io/downloads/paper)에서 26.2(build 121
   이상) 서버 jar를 받는다. `eula.txt`에 `eula=true`로 동의한다. 서버를 실행하는 Java는
   **반드시 25 이상**이어야 한다 (`java -version`으로 확인, 아니면 서버 자체가 기동하지 않는다).
2. **플러그인 설치** — `mvn package`로 빌드했거나 [Releases](../../releases)에서 받은
   `Beotigi-1.0.0.jar`를 서버의 `plugins/` 폴더에 넣고 서버를 시작한다. 별도 void 월드
   플러그인은 필요 없다 — Beotigi가 자체 빈 청크 제너레이터(`VoidChunkGenerator`)로
   `beotigi_skyblock`이라는 전용 월드를 최초 기동 시 스스로 만들고, 그 위에 시작 섬 3개를
   직접 짓는다. 콘솔에 아래 로그가 뜨면 정상 진행된 것이다:
   ```
   [Beotigi] 스카이블럭 월드가 없어서 새로 만든다: beotigi_skyblock
   [Beotigi] 시작 섬 3개를 미리 짓는다...
   [Beotigi] Beotigi 재해 시스템이 조용히 깨어났습니다.
   ```
   (이 과정은 서버당 딱 한 번만 실행된다 — 이미 지어진 섬은 재시작해도 다시 덮어쓰지 않는다.)
3. **바로 플레이** — 플레이어가 서버에 처음 접속하면 자동으로 숲/바위/초원 섬 중 아직 가장
   사람이 적은 곳에 배정되어 그 자리로 순간이동한다. 3명이 순서대로 들어오면 자연스럽게
   한 명씩 서로 다른 섬을 받게 된다. 어떤 섬을 받았는지는 재접속해도 유지된다
   (`plugins/Beotigi/assignments.yml`에 저장).
4. **(선택) 클라이언트용 미니맵** — 서버 쪽엔 미니맵 렌더링 기능이 없다. 녹화용 클라이언트에
   [Xaero's Minimap](https://www.curseforge.com/minecraft/mc-mods/xaeros-minimap) 같은 모드를
   설치하면 서버 설정 없이 바로 동작한다.
5. **동작 확인** — 관리자 권한으로 `/beotigi status`를 입력해 현재 날씨 단계 등이 뜨는지
   확인한다. 필요하면 `/beotigi forcestorm`, `/beotigi forcemeteor` 등으로 재해를 강제
   발동시켜 테스트할 수 있다 (아래 "관리자 명령어" 표 참고). 수동으로 섬을 하나 더 짓고
   싶으면 `/island forest|rock|plains`도 여전히 쓸 수 있다 (4번째 인원, 재건축 등).

## 설계 철학 — "정해진 스케줄"이 아니라 "매번 확률을 굴린다"

이 플러그인의 거의 모든 시스템은 **고정된 타이머가 아니라 매 체크(보통 몇 초~1분 간격)마다
확률을 새로 굴리는 방식**으로 동작한다. 그래서:

- "폭풍은 언제나 정확히 3분 뒤에 심해진다" 같은 건 없다. 어떤 날은 비가 와도 아무 일 없이
  지나가고, 어떤 날은 비가 오자마자 몇 초 만에 SEVERE_STORM까지 튄다
  (`weather.sudden-jump-chance-per-second` — 예고 없이 한 번에 건너뛰는 경우).
- 화산도 "휴면 5분 → 연기 3분 → 용암 2분 → 폭발" 같은 고정 스케줄이 아니라, 5초마다
  "다음 단계로 넘어갈까?"를 확률로 묻는다 (`volcano.*-advance-chance`). 그래서 어떤 화산은
  몇 분 만에 터지고, 어떤 화산은 한참 잠들어 있다가 갑자기 깨어난다.
- 밤 이벤트(붉은 달/유성우/안개/박쥐 떼)도 "매일 밤 정각에 체크" 방식이 아니라, 밤 동안
  계속 낮은 확률로 굴려서 언제 터질지 예측할 수 없게 했다 (`NightEventManager`,
  `CHECKS_PER_NIGHT` 기준으로 하룻밤 전체 확률은 기존 설정값과 비슷하게 맞춰뒀다).
- 유일한 예외는 물리 법칙에 가까운 것들 — 예를 들어 화재 전파, 침수 후 물 빠짐 타이머,
  운석이 떨어지는 물리적 낙하 시간 등은 확률이 아니라 실제로 그렇게 되어야 하는 것들이라
  그대로 뒀다.
- **채팅 안내 = HUD 아님.** 큰 사건 직전/직후에 "바람이 심상치 않다...", "땅이 울리기
  시작한다!" 같은 짧은 분위기 대사를 채팅으로 한 줄 보낸다 (`ChatAnnouncer`). 정확한 초
  단위 숫자나 진행률 바는 절대 없다 — 게이지 대신 대사로, 카운트다운 대신 낌새로.

## 들어있는 기능

기획서의 18개 섹션을 전부 구현했다. 모든 수치(격화 확률, 발생 빈도, 반경 등)는
`config.yml`에서 조절 가능하며, 그 수치 자체는 플레이어에게 노출되지 않는다.

### 🏝️ 시작 & 자동 배정
- **자동 스카이블럭 월드 (`SkyblockWorldManager`, `VoidChunkGenerator`)** — 플러그인 자체
  빈 청크 제너레이터로 `beotigi_skyblock` 월드를 최초 기동 시 자동 생성. 시작 섬 3개를
  미리 지어두고, `World`의 PersistentDataContainer에 "이미 지었음" 플래그를 남겨 재시작해도
  중복 시공하지 않는다.
- **첫 접속 자동 배정 (`PlayerAssignmentStore`)** — `PlayerJoinEvent`에서 아직 섬을 배정받지
  않은 플레이어를 감지해, 현재 가장 인원이 적은 섬 타입으로 배정하고 그 자리로 텔레포트한다.
  배정 결과는 `assignments.yml`에 저장되어 재시작/재접속에도 유지된다.
- **시작 섬 3종 (`IslandManager`, `IslandType`)** — 숲섬(나무 5그루 + 잔디, 목재 자원),
  바위섬(석탄/철 노출 광맥 + 돌무더기, 채광 자원), 초원섬(작은 밀/당근 농장 + 양/닭,
  농업·목축 자원). 처음부터 자원 구성이 다르게 설계되어 "나무 부족하면 나한테 와" 같은
  자연스러운 협력을 유도한다.

### 🌩️ 날씨 & 재해
- **날씨 격화 (`WeatherManager`)** — 비가 오면 `CALM → LIGHT_RAIN → STORM → SEVERE_STORM`
  단계로 매초 확률에 따라 격화(`escalation-chance-per-second`, 기본 0.4%)하거나 약화
  (`deescalation-chance-per-second`, 기본 1%). 아주 가끔(기본 0.06%/초) 단계를 다 건너뛰고
  한 번에 SEVERE_STORM까지 튀기도 한다. STORM 이상에서는 하늘이 뚫린 곳의 플레이어를 바람이
  밀어내고(`wind-push-strength`), 나뭇잎/횃불/유리판 같은 가벼운 블록이 날아간다
  (`light-block-damage-chance-per-second`). SEVERE_STORM에서는 근처 나무가 통나무 단위로
  실제로 쓰러진다(`tree-fall-chance-per-second`, `FallingBlock`으로 시각화).
- **번개폭풍 (`LightningFireManager`)** — STORM 이상일 때 자연 번개 외에 추가 번개를
  내리친다(`extra-strike-chance-per-second`). 화재가 나무 → 건물로 번지는 건 순수 바닐라
  화재 전파 그대로 사용 — 따로 불을 지르는 코드는 없다.
- **폭우/침수 (`FloodManager`)** — 폭풍이 강할 때 근처 농지(흙/잔디/농지 블록) 위에 물이
  차오른다(`flood-chance-per-second`). 우리가 채운 물만 따로 추적해뒀다가, 일정 시간
  (`recede-after-seconds`, 기본 90초) 뒤 자동으로 빠진다 — 원래 지형은 파괴하지 않는다.
- **운석 (`MeteorManager`)** — 밤에 낮은 확률로(`chance-per-minute`) 하늘에서 마그마
  블록이 실제 물리 낙하하며(불꽃 파티클 트레일 포함) 떨어진다. 충돌 지점에 반경
  `crater-radius`의 크레이터를 만들고(가장자리는 블랙스톤/현무암으로), 중심에 철/금/다이아
  ·에메랄드·(희귀하게) 고대 잔해가 담긴 상자를 남긴다.
- **유성우** — 운석의 "약한 버전"이 짧은 시간에 6~12개 연속으로 떨어진다. 크레이터가
  작고 전리품 상자가 없다. 밤 이벤트로만 트리거된다.
- **공허 폭풍 (`VoidStormManager`)** — 아주 드문(`chance-per-hour`) 후반부 이벤트.
  시작하면 채팅 경고 후 몇 초 뒤부터, 섬 가장자리에서 아래로 3칸 이상 뚫려 공허에 노출된
  블록이 계속 사라진다. 이벤트 전체에서 삭제되는 블록 수에 안전 상한(150개)을 둬서 섬이
  통째로 사라지는 사고는 나지 않는다.
- **구조 붕괴 (`StructuralCollapseManager`)** — 기둥 없이 멀리 뻗은 다리/구조물을 BFS로
  찾아낸다 (아래로 3칸 이상 뚫린 블록에서 시작해, 마찬가지로 지지대 없는 이웃 블록만 따라가며
  연결된 덩어리를 탐색, 최대 `support-search-limit`개까지). 덩어리 크기가 10개 이상이면
  "위태로운 구조물"로 판정하고, 폭풍이 심할 때 확률적으로 그 중 몇 블록을 `FallingBlock`으로
  떨어뜨린다. **플레이어가 실제로 지은 구조(특히 기둥 없는 다리)에 반응하는 유일한 재해.**
- **화산 (`VolcanoManager`)** — 화산섬은 `휴면 → 연기 → 소규모 용암 → 폭발 → 냉각 → (다시 휴면)`
  주기를 스스로 반복한다. 모든 전환이 5초마다 확률을 굴리는 방식(`volcano.*-advance-chance`)이라
  화산마다 주기가 제각각이다. 용암 단계 끝에는 "땅이 울리기 시작한다!" 채팅 경고 후 3~18초
  사이 무작위 지연을 두고 실제로 폭발한다 — 폭발 시 용암탄 8개가 사방으로 날아가 주변 섬까지
  불을 낼 수 있다.
- **밤 이벤트 (`NightEventManager`)** — 밤 동안 계속 낮은 확률로 각각 독립적으로 굴림
  (하룻밤에 이벤트당 최대 1회, 하지만 밤의 몇 분째에 터질지는 무작위):
  - 🌕 붉은 달: 근처에 좀비/스켈레톤/스파이더가 갑자기 무더기로 소환됨 (달 색상 자체를 바꾸는
    공식 API가 없어 몹 압박으로 구현 — "알려진 제한" 참고)
  - ☄️ 유성우, 🌫️ 이상한 안개(`DARKNESS` 효과 + 안개 파티클 반복), 🦇 거대 박쥐 떼

### 🏝️ 섬 & 발견
- **새로운 섬 발견 (`IslandDiscoveryManager`)** — 10분마다 확률적으로(`chance-per-interval`),
  스폰에서 300~1200블록 떨어진 임의 지점에 9종 중 하나가 나타난다 (이미 발견된 섬과는
  최소 150블록 간격 유지): 🌴 정글(작은 정글나무), ❄️ 빙하(눈+얼음), 🏜️ 사막(선인장+마른 덤불),
  🌋 화산(등록되면 `VolcanoManager`가 관리 시작), 🌸 꽃(6종 꽃밭), 🍄 버섯(거대 버섯 생성),
  ⛏️ 광산(광맥 14개 + 전리품 상자), 🏚️ 폐허(무너진 돌담 + 상자 1개), 🏰 성(더 크고 값진
  돌벽돌 구조 + 상자 2개). 텍스트 설명은 전혀 없다 — 미니맵에 뭔가 보이면 직접 가서 확인.
- **생태계 (`EcosystemManager`)** — 토끼(=쥐 컨셉, 바닐라 토끼가 이미 당근을 갉아먹는 걸
  활용)가 농지 근처에서 일정 수 미만이면 계속 새끼를 낳고, 방치하면 계속 불어난다. 작물
  근처에 벌이 한 마리도 없으면 `BlockGrowEvent`를 확률적으로 취소해 작물 성장이 가끔
  멈춘다. 양이 5마리 이상 몰려 있으면 확률적으로 야생 늑대가 나타나 사냥한다 (바닐라 늑대
  AI가 알아서 양을 공격 — 커스텀 전투 로직 없음).
- **자연 성장 (`IslandGrowthManager`)** — 잔디 위에 꽃/식물이 저절로 퍼지고, 사방이 조금
  높은 지형에 둘러싸인 "웅덩이" 지형을 감지하면 확률적으로 작은 연못이 생긴다. 초원에는
  소/양/돼지/닭이 상한선(`max-passive-animals-per-scan-area`, 기본 10마리) 안에서 천천히
  늘어난다.

### 🏘️ 주민 & 교역
- **주민 이주 (`VillagerMigrationManager`)** — 반경 10블록 안에 침대(`*_BED`)와 문(`*_DOOR`)이
  모두 있으면 "집"으로 판정하고, 확률적으로 주민이 자연스럽게 찾아온다(`migration-chance`).
  마을 인구가 `shop-threshold-villagers`(기본 4명)를 넘으면 새로 온 주민에게 무작위 직업
  (농부/사서/대장장이/성직자/어부/양치기/도축업자 등 12종)과 그에 맞는 실제 작업대(작곡가,
  독서대, 용광로, 대장간, 훈연기 등)를 근처 빈 자리에 배정한다 — **이게 곧 "HUD 없는
  상점"**: 바닐라 주민 거래 GUI를 그대로 활용하기 때문에 커스텀 상점 UI가 필요 없다.
- **떠돌이 상인 (`TravelingMerchantManager`)** — 아무도 부르지 않았는데 확률적으로
  (`chance-per-hour`) 근처에 나타나(라마 동반), 에메랄드 교역 몇 개와 함께 특수 아이템
  1~2종을 비싼 값(에메랄드 16~32개)에 판다. `stay-minutes`(기본 5분) 후 알아서 사라진다.

### 🐉 생물 & 아이템
- **하늘 생물 (`SkyCreatureManager`)** — `Attribute.SCALE`로 크기를 키운 가스트("하늘고래",
  2.2배, 원래 가스트 AI 그대로라 가끔 위협적일 수 있음), 팬텀("거대한 새", 1.8배, 원래도
  플레이어 주위를 맴돌다 급강하 공격하는 AI라 "가끔 공격할 수도 있다"는 컨셉과 잘 맞음),
  박쥐 무리("거대 박쥐 떼", 5~8마리, 1.6배)가 확률적으로 등장. 사냥 목표가 아니라 그냥
  세계에 존재하는 생물 — 동시 존재 개수 상한(`max-concurrent`, 기본 3)을 둬서 화면이
  생물로 도배되진 않는다.
- **특수 아이템 (`SpecialItemManager`)** — 운석 크레이터/폐허/성/광산 상자, 떠돌이 상인
  거래에서 확률적으로 발견:
  - 🪁 **글라이더** — 엘리트라를 이름만 바꿔 그대로 사용 (진짜로 활공 가능).
  - 🧲 **섬 연결석** — 사용하면 가장 가까운 "발견된 섬"까지 최대 80블록의 임시 다리
    (패킹 얼음)를 놓는다. 섬 전체를 물리적으로 끌어당기는 건 너무 파괴적이라 이렇게
    재해석했다.
  - 🌱 **생명의 씨앗** — 클릭한 지점 반경 3칸의 죽은 블록(돌/블랙스톤/모래/자갈 등)을
    잔디로 되살리고, 35% 확률로 꽃도 함께 피운다.
  - 🏗️ **건설 코어** — 딛고 선 땅과 같은 재질로 반경 3칸을 채워 넣어 땅을 넓힌다.
  - 🌪️ **바람의 깃털** — 사용하면 슬로우 폴링 30초 + 살짝 위로 튕겨 올라가는 상승기류
    효과. 강풍에 휩쓸려도 죽지 않게 해주는 보험.

## 알려진 제한

- **미니맵** — 서버 플러그인만으로는 진짜 미니맵을 그릴 수 없다 (Bukkit/Paper API는 클라이언트
  HUD를 렌더링할 방법이 없음). **Xaero's Minimap 같은 클라이언트 모드는 서버 쪽 코드 없이도
  그대로 작동**하니, 녹화용 클라이언트에 설치하는 것으로 이 요구사항을 충족하는 걸 권장한다.
  BlueMap/Dynmap 같은 웹 지도도 대안.
- **붉은 달 시각 효과** — 달 텍스처/색상을 바꾸는 공식 API가 없어서, "붉은 달"은 시각적 변화
  대신 몹 압박(적대 몹 급증)으로 구현했다. 리소스팩을 곁들이면 진짜 색도 바꿀 수 있다.
  안개도 마찬가지로 `DARKNESS` 포션 효과 + 파티클로 근사했다 (실제 클라이언트 렌더 안개는
  리소스팩/셰이더 영역).
- **채팅 안내의 정확도** — 화산 폭발처럼 실제 지연이 있는 경우를 빼면, 대부분의 채팅 경고는
  "지금 막 상태가 바뀌었다"는 사후 알림에 가깝다 (정확한 사전 카운트다운이 아니다) — 이건
  의도된 것: 완전한 침묵과 스포일러성 정밀 타이머 사이의 중간 지점을 노린 설계다.
- **자동 생성된 `beotigi_skyblock` 월드의 저장 위치** — Bukkit이 커스텀 NORMAL 환경 월드를
  루트의 별도 폴더가 아니라 `world/dimensions/minecraft/beotigi_skyblock/` 하위에 저장한다
  (최신 Paper의 커스텀 차원 저장 방식). 백업 스크립트를 쓴다면 이 경로도 포함해야 한다.
- Folia(멀티스레드 리전) 미지원. 일반 Paper 서버 기준으로 `BukkitScheduler`를 사용.
- 화산 진행 단계, 발견된 섬 목록(위치/타입) 등은 메모리에만 저장된다. 서버 재시작 시
  초기화됨 (단, 플레이어-섬 배정과 이미 지어진 시작 섬은 파일에 저장되어 유지된다) —
  장기 녹화라면 재시작을 피하는 걸 권장.
